# ぷよぷよ — 実装方針

`1_requirements.md` の受け入れ条件を満たすための設計。
既存のテトリス（`tetris_board.py` / `tetromino.py` / `tetris_scene.py`）と同じ
**「描画を持たないロジック層」＋「シーン層」** の2層構成を踏襲する。

---

## 1. 全体構成

| レイヤ | ファイル | 責務 | pygame 依存 |
|--------|----------|------|-------------|
| ロジック | `game_objects/puyo/puyo_board.py` | 盤面配列・連結判定・消去・落下・得点 | **なし** |
| ロジック | `game_objects/puyo/puyo_pair.py` | 組ぷよの座標計算・回転・壁蹴り | **なし** |
| シーン | `scenes/puyo_puyo_scene.py` | 状態機械・入力・描画・SE・HUD | あり |

ロジック層を pygame 非依存にすることで、`1_requirements.md` の
「ヘッドレスのデバッグスクリプトで検証」がそのまま可能になる（テトリスと同じ方針）。

---

## 2. データ表現

### 盤面

```python
self.grid = [[None] * 6 for _ in range(12)]   # grid[row][col]
```

- 空きセルは `None`、ぷよがあるセルは色キー文字列 `"R" / "G" / "B" / "Y"`。
- テトリスの `Board.grid` と同じ「`None` か種類キー」の表現に揃える。

### 色

`PUYO_KINDS = ["R", "G", "B", "Y"]`（4色・原作準拠）。
色 RGB は `config.py` に `COLOR_PUYO_R` などで定義し、`puyo_pair.py` の
`COLORS` 辞書で引く（テトリスの `COLORS` と同じ形）。

---

## 3. 組ぷよ（`puyo_pair.py`）

### 表現

軸ぷよ（`x`, `y`）＋ 子ぷよの向き `rot`（0〜3）で表す。
テトリスのように形状テーブルは持たず、向きから子の相対座標を計算する方がシンプル。

```python
OFFSETS = [(0, -1), (1, 0), (0, 1), (-1, 0)]  # rot 0=上, 1=右, 2=下, 3=左
```

| メソッド | 内容 |
|----------|------|
| `axis_cell(x=None, y=None)` | 軸ぷよの絶対座標 `(x, y)` |
| `child_cell(rot=None, x=None, y=None)` | 子ぷよの絶対座標 |
| `cells(...)` | `[軸, 子]` の2セル。テトリスの `cells()` と同じ役割 |
| `next_rotation(direction)` | `(rot + direction) % 4` |

`direction=1` が右回転（X キー）、`-1` が左回転（Z キー）。

### 回転と壁蹴り

回転後に子ぷよが壁・既存ぷよと重なる場合、**軸ぷよを反対側へ1マスずらして**成立させる
（原作の壁際回転）。試行順は「その場 → 軸を子の反対方向へ1マス」。

```
rot=1（子が右）で右端にいる → X で rot=2 にはできるが
rot=3（子が左）へ回すとき壁に当たる → 軸を右へ1マス押して成立
```

両方失敗した場合は回転しない（クイックターンは今回は入れない ＝ スコープ外）。

## 4. 盤面ロジック（`puyo_board.py`）

描画を持たない純ロジック。主要メソッドは以下。

| メソッド | 内容 |
|----------|------|
| `is_valid(cells)` | 全セルが盤面内かつ空きか（`cy < 0` は出現直後として許容） |
| `lock(pair)` | 組ぷよの2セルを `grid` に固定 |
| `apply_gravity()` | 全列で浮いているぷよを下へ詰める。動いたら `True` |
| `find_groups()` | 同色4個以上の連結グループを列挙（**上下左右のみ・斜めは不可**） |
| `pop_groups(groups)` | 該当セルを `None` にし、消したぷよ数を返す |
| `is_dead()` | 出現位置（3列目最上段）が埋まっているか |

### 連結判定

`find_groups()` は BFS（幅優先探索）で同色の連結成分を求め、サイズ 4 以上のものだけ返す。
訪問済みフラグは 6×12 の 2次元リストで持つ。盤面が小さいので毎回全探索で十分速い。

```
for each cell:
    if 未訪問 and 色あり:
        BFS で同色連結成分を集める（隣接は上下左右の4方向）
        len(group) >= 4 なら結果に追加
```

### ちぎり（独立落下）

`apply_gravity()` は組ぷよ単位ではなく**セル単位**で処理する。
列ごとに「下から詰め直す」だけで、軸と子が別々に落ちる原作の挙動が自然に再現される。

```python
for col in range(cols):
    stack = [grid[r][col] for r in range(rows) if grid[r][col] is not None]
    # 下端から stack を積み直し、残りは None
```

これで「片方だけ空中に残る → 下まで落ちる」が実現できる（受け入れ条件のちぎり）。

## 5. 得点計算

原作の連鎖ボーナス方式を簡易化して採用する。

```
得点 = 消したぷよ数 × 10 × 連鎖ボーナス
```

連鎖ボーナス（`PUYO_CHAIN_BONUS`）は `config.py` にテーブルで持つ：

| 連鎖 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8+ |
|------|---|---|---|---|---|---|---|-----|
| 倍率 | 1 | 8 | 16 | 32 | 64 | 96 | 128 | 160 |

テーブル長を超える連鎖は最後の値で頭打ちにする。
**2連鎖目で一気に8倍**になるため、「連鎖が伸びるほど得点が跳ね上がる」という
受け入れ条件を素直に満たせる。連結ボーナス・複色ボーナスは入れない（スコープ外）。

## 6. 状態機械（`puyo_puyo_scene.py`）

ぷよぷよはテトリスと違い「消去 → 落下 → 再判定」の**連鎖アニメーション**があるため、
その間は入力を止める必要がある。以下の4状態を持つ。

```
        ┌─────────────────────────────────────────┐
        │                                         │
        v                                         │
    [play] ──着地──> [vanish] ──> [drop] ──連鎖あり─┘
      │                 消去演出     落下演出
      │                                  │
      │                              連鎖なし
      │                                  v
      └──出現できない──────────────> [over]
```

| 状態 | 内容 | 入力 |
|------|------|------|
| `play` | 組ぷよが落下中。操作可能 | 受付 |
| `vanish` | 消えるぷよを点滅表示（`PUYO_VANISH_TIME` 秒） | **無視** |
| `drop` | 浮いたぷよを落とす（`PUYO_DROP_TIME` 秒） | **無視** |
| `over` | ゲームオーバー。オーバーレイ表示 | `R` のみ |

`handle_input` の先頭で `if self.state not in ("play", "over"): return` として
アニメーション中の入力を一括で弾く（受け入れ条件の「入力ロック」）。

### 着地から連鎖までの流れ

1. `play` で落下 → 下に置けなくなったら `lock()` → SE `lock`
2. `apply_gravity()`（ちぎり）→ `find_groups()`
3. グループあり → `chain += 1`、`vanish` へ。なければ次の組ぷよを出す
4. `vanish` 終了 → `pop_groups()` → 得点加算 → SE（1連鎖 `line` / 2連鎖以上 `levelup`）→ `drop` へ
5. `drop` 終了 → `apply_gravity()` → 再び `find_groups()` → あれば 3 へ戻る（連鎖継続）
6. 連鎖終了 → `chain = 0` → 次の組ぷよを出現。置けなければ `over`

---

## 7. NEXT キュー（2手先）

```python
self.next_queue = [random_pair(), random_pair()]   # [次, その次]
```

現在の組ぷよを消費するときに `pop(0)` して末尾へ1つ補充する（先入れ先出し）。
これで常に「次」「その次」の2つが見える状態を保つ。

## 8. 画面レイアウト

`1_requirements.md` で挙げた「右パネルが窮屈になる懸念」への対応。
盤面 240×480px、セル 40px。**盤面を左に寄せて右パネル幅を確保する**。

```
┌──────────────────────────────────────────────┐ 800
│                                              │
│   ┌────────────┐   NEXT   ┌──┐               │
│   │            │          │  │  ← 40px       │
│   │            │   NEXT2  ┌─┐                │
│   │  盤面      │          └─┘  ← 28px（小）  │
│   │  6 x 12    │                             │
│   │  240x480   │   SCORE                     │
│   │            │   001230                    │
│   │            │                             │
│   │            │   CHAIN                     │
│   │            │   3 CHAIN!                  │
│   │            │                             │
│   └────────────┘   CONTROLS                  │
│                    <- -> : MOVE              │
│    x=60, y=60      v (HOLD): DROP            │
│                    X : ROTATE R              │
│                    Z : ROTATE L              │
│                    R : RESTART               │
│                    ESC : MENU                │
└──────────────────────────────────────────────┘ 600
```

- 盤面 X = 60、Y = 60（テトリスの 210 より左に寄せ、パネルに約 430px 確保）
- パネル X = 340
- NEXT2 はセル 28px で描き、「次」より小さく見せて優先度を示す
- CONTROLS は画面下から逆算して配置（テトリスの `_draw_side_panel` と同じ手法）

縦の必要量：NEXT(約100) + NEXT2(約90) + SCORE(約80) + CHAIN(約80) + CONTROLS(約160)
≒ 510px < 540px（60〜600）に収まる見込み。実画面で確認して微調整する。

## 9. `config.py` に追加する定数（`PUYO_` 接頭辞）

```python
PUYO_COLS = 6                  # 盤面の列数（原作準拠）
PUYO_ROWS = 12                 # 盤面の行数（原作準拠）
PUYO_CELL = 40                 # 1マスの辺（px）
PUYO_BOARD_X = 60              # 盤面左上 X
PUYO_BOARD_Y = 60              # 盤面左上 Y
PUYO_SPAWN_COL = 2             # 出現列（0始まりで3列目）
PUYO_BASE_FALL = 0.7           # レベル1の落下間隔（秒）
PUYO_FALL_STEP = 0.05          # レベルごとの短縮量
PUYO_MIN_FALL = 0.10           # 落下間隔の下限
PUYO_SOFT_DROP = 0.04          # ソフトドロップ間隔（秒）
PUYO_VANISH_TIME = 0.45        # 消去演出の時間（秒）
PUYO_DROP_TIME = 0.18          # 落下演出の時間（秒）
PUYO_POP_SCORE = 10            # ぷよ1個あたりの基礎点
PUYO_CHAIN_BONUS = [1, 8, 16, 32, 64, 96, 128, 160]  # 連鎖ボーナス倍率
COLOR_PUYO_R / _G / _B / _Y    # ぷよ4色
COLOR_PUYO_GRID / _FRAME       # 盤面のグリッド線・枠
```

レベルは「消したぷよの累計 ÷ 30 + 1」とし、落下間隔を少しずつ短くする
（テトリスの `_calc_fall_interval` と同じ考え方）。

## 10. 描画方針

- ぷよは**円**で描く（テトリスの四角ブロックと差別化）。
  `pygame.draw.circle` で本体 → 左上に小さな白い光沢 → 中央に目（白丸＋黒目）。
  目を入れるだけで一気に「ぷよぷよらしさ」が出るので必ず入れる。
- 消去演出（`vanish`）は該当ぷよを点滅させる（`int(t * 20) % 2` で表示/非表示）。
- 連鎖表示は `CHAIN` パネルに `"3 CHAIN!"` を黄色で出し、連鎖中のみ表示。

## 11. メニューサムネイル

`menu_thumbnails.py` に `_draw_puyo_puyo(surf, w, h)` を追加し `_DRAWERS` に登録。
黒背景に色違いのぷよ（目つきの円）を数個積み上げた絵にする。
既存の `_draw_tetris` / `_draw_snake` と同じくプリミティブのみで描く（画像ファイル不使用）。

## 12. 影響範囲

既存ゲームのコードには**一切手を入れない**。変更は以下の追記のみ：

| ファイル | 変更内容 | リスク |
|----------|----------|--------|
| `config.py` | `PUYO_` 定数を末尾に追記 | なし（接頭辞で衝突回避） |
| `menu_scene.py` | `GAMES` に1行追加 | 低。カードが12枚になり 4列×3行に収まる |
| `menu_thumbnails.py` | 描画関数1つ＋登録1行 | なし |
| `main.py` | import 1行＋`register_scene` 1行 | なし |

> `GAMES` は現在11件。1件追加で12件となり、4列ちょうど3行に収まる
> （`_card_rect` の最終行中央寄せロジックにより、むしろ現在より整った見た目になる）。

## 13. 検証方法

1. **ヘッドレス検証**（scratchpad にデバッグスクリプトを置く）
   - 連結判定：4個並べて消える／3個では消えないこと
   - 斜めはつながらないこと
   - ちぎり：片方だけ空中に残ったぷよが落ちること
   - 連鎖：意図的に組んだ盤面で2連鎖・3連鎖が発生すること
   - 得点：連鎖ボーナスが正しく掛かること
2. **実起動確認**：`python src/main.py` でメニュー → PUYO PUYO → プレイ →
   連鎖 → ゲームオーバー → `R` リスタート → `ESC` メニューの流れを目視確認
